# Replacements for units out of the build, and the entry point

Port code that is compiled into the client with the client's own flags (`bf_client_flags`; listed in `BF_CLIENT_PORT_SOURCES` in the root `CMakeLists.txt`) because it stands in for a unit of `sources.mk` that the port does not build (`BF_CLIENT_EXCLUDE`, implementation plan M2.5).

| File | Replaces | What it does |
|---|---|---|
| `bf_client_state.cpp` | (new) | The client's state for the control socket: `bf_port_mode` maps the mode manager and the login sub-mode to PROTOCOL.md's `mode` (`login`, `connecting`, `servers`, `charselect`, `makechar`, `loading`, `game`, `quitting`) and the client's own name (`LSM_IDENTRY`, `MT_GAME`). |
| `bf_crash.cpp` | `src/ExceptionHandler.cpp` (crash dialog, minidump) | A static constructor installs a handler for SIGSEGV, SIGBUS, SIGILL, SIGFPE, SIGABRT and SIGTRAP on an alternate stack. On a crash it writes the signal, the faulting address, pc, lr and a backtrace as `crash:` lines through the trace (category `err`, always on), dumps the counters, then re-raises with the default action so the system's crash report still sees the fault. `BF_NO_CRASH_HANDLER=1` turns it off. It also defines `ExceptionFilter`, the one name of the old unit that `WinMain` uses (`SetUnhandledExceptionFilter`, which the Win32 adapter provides as a stub). |

The other removals of M2.5 are inside `src/`, under `BF_PORT`, because that was the smaller change:

- **GameGuard**: `src/base/FindHack.cpp` makes its four entry points (`SetHwnd`, `SendID`, `ExitFindHack`, `Auth2`) empty and leaves out `FindHack1`, `FindHack2`, `ProcessFindHack` and the monitor callback, which nothing calls. `CNPGameLib`'s inline wrappers are no longer used, so no GameGuard function is referenced.
- **Bink**: `src/movie/CBink.cpp` keeps the class and reports no movie (`Break` returns 1, `Pause` does nothing, `OpenningMain` writes a `ui` trace line); `CBink.h` no longer includes the Bink SDK headers.
- **Granny**: `src/resource/Model.cpp` keeps `C3dGrannyModelRes` and `C3dGrannyBoneRes` and loads nothing (`Load` and `AddBone` return false with a `res` trace line and the counter `granny model not loaded`); `CGameMode::NewNpc` and `MakeGrannyCorpse3d` create no Granny actor, so the `.gr2` job names draw nothing (NewNpc falls back to `CNpc`). The six SDK functions the actor classes still name are empty there too. `src/granny/granny.h` stays: it is declarations only.

## The entry point and the start-up glue (M3.2, M3.7)

The library `bf_port_main` (root `CMakeLists.txt`) is port code, compiled with `bf_compat_flags` and the native modules' headers, and linked into the client; the client's own sources reach it through `port/compat/include/bf_port.h` under `BF_PORT`.

| File | What it does |
|---|---|
| `bf_main.cpp` | `main`. Takes the port's flags out of the command line (`--headless`, `--control <path>` / `--control=<path>`, Finder's `-psn_`), joins the rest with spaces as `lpCmdLine` and calls the client's `WinMain`. Before that, unless headless: `bf_app_init` (single instance "main"; a second launch exits 0), `bf_app_set_clock` (the sys clock in ms), `bf_prefs_choose_game_folder` (0: quit, -1: exit 1), `bf_prefs_install_menu_item`, `bf_compat_input_set_scale_setting(Display/UIScale, default 0 = auto)`. Opens the control socket when asked (`bf_control_path_from_args`): hooks `quit` (WM_CLOSE to the window, as Cmd+Q), `capture` (`bf_gfx_capture_png`), the pointer mapping through `bf_view`; state parts `mode` and `detail`; the event `mode`. Defines the `bf_port_*` functions of `bf_port.h`. |
| | `bf_port_start_graphics`: called by `WinMain` right after `InitApp` (the input adapter's `CreateWindowExA` has made the window, its layer and the view): creates the gfx device on `bf_app_window_metal_layer()` at the view's logical size and UI scale, attaches it to the view and hands it to the Direct3D adapter, before `SetupDriver2`. |
| | `bf_port_frame`: called at the top of `CheckSystemMessage`, i.e. once per frame of both modes. When the gfx device has presented a new frame it calls `bf_control_frame_done` (a capture reads the target, which still holds that frame), reports a `mode` change as an event, then `bf_control_poll`. Nothing without a socket. |
| | The end of the process: an `atexit` handler registered first in `main` saves the settings, writes the counters (when any trace category beyond `err`/`stub` is on), flushes and calls `_exit`. The client's static destructors (`CFileMgr`, `CSkinMgr`) would otherwise run after the port's own statics, in no defined order across units, and call into the file tables after they are gone; they release only what the system reclaims. An `exit(n)` elsewhere therefore ends with status 0. |
| `bf_zlib.cpp` | `bf_zlib_uncompress`/`bf_zlib_compress` on `bf_codec_inflate`/`deflate`: `common.h` maps the client's `uncompress`/`compress` to them, because its declarations take a 32-bit `DWORD *` length and the system zlib's `uLongf` is 64 bits. |
| `bf_crt.cpp` | The Visual C++ runtime names macOS lacks, as real functions: `itoa`, `_itoa`, `_ltoa` (radix 2–36, sign only in radix 10), `strlwr`, `_strlwr`, `strupr`, `_strupr` (ASCII only, as the "C" locale), `_lrotl`, `_lrotr`. `spawnl` is a stub (`BF_STUB`, returns -1, `ENOENT`): its callers start `runzip.exe` (zipped skins) and `findhack.exe` (GameGuard). |

The client's call sites under `BF_PORT`: `WinMain.cpp` (`bf_port_start_graphics` after `InitApp`, `bf_port_frame` in `CheckSystemMessage`, the `--headless` stop), `common.h` (zlib), `resource/Bitmap.cpp` `LoadJPGData` and `3dlib/Renderer.cpp` `SaveJPG` (JPEG through `bf_codec_jpeg_*`; rows unpadded, as the client's own loops read and write them; the screenshot path resolved with `bf_file_resolve`), `3dlib/Device.cpp` (no `TestScreen`), `Mode.cpp` (`CMode::GetSubMode`, declared but never defined in the reconstruction).
