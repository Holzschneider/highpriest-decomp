# compat/d3d: DirectDraw 7 and Direct3D 7 on port/native/gfx

Stage A adapter (M4.4; M11 deletes it). It gives `src/3dlib` the DirectDraw 7 / Direct3D 7 objects it calls, drawing through [`port/native/gfx`](../../native/gfx), so the renderer runs unchanged. What the client does with each call, and how it maps onto gfx, is the gfx module's [`D3D-USAGE.md`](../../native/gfx/D3D-USAGE.md); this adapter is written to it.

## Interface

[`include/bf_compat_d3d.h`](include/bf_compat_d3d.h):

- `bf_compat_d3d_set_device(bf_gfx_device *)`: **the client's start-up must call it** after the application module has created the window, its layer and the gfx device (`bf_gfx_create` with the window's logical size and UI scale), and before `C3dDevice::Init` (`SetupDriver2` in `WinMain.cpp`). Without it `DirectDrawCreateEx` fails with `DDERR_NODIRECTDRAWHW`. At exit call it with `NULL` before `bf_gfx_destroy`: it destroys the gfx textures of surfaces the client still holds, so the order of clean-up does not matter.
- `bf_compat_d3d_get_device`, `bf_compat_d3d_get_stats` (render-target locks, read-backs, write-backs).

The adapter creates no window and no device. The client sees the gfx device's logical size as the display mode and the primary surface, in 32-bit X8R8G8B8. If the client's back buffer is created at another size (its `GetClientRect` disagrees with gfx), the adapter resizes the gfx device to the client's size at the same UI scale and traces it.

Other names: `DirectDrawCreateEx` and the DirectDraw/Direct3D GUIDs of `ddraw.h` and `d3d.h` (`IID_IDirectDraw7`, `IID_IDirect3D7`, `IID_IDirect3DHALDevice`, ...), which the original took from `dxguid.lib`. The client calls no other DirectDraw entry point (`DirectDrawCreate` and `DirectDrawEnumerateEx` are not defined). A surface DC is a `bf_text_canvas` of `port/native/text` (M11.8): the library links `bf_text`.

## How the details that decide the picture are handled

- **Half pixel, texel offset, `TestScreen`.** The gfx module shifts positions by +0.5 native pixel, so Direct3D 7's pixel centres hold and the right texel offset is 0.5, the value `CTexture::m_uOffset/m_vOffset` start with. `TestScreen` runs unchanged and picks exactly that: with a 32-bit frame buffer its decoder reads `(WORD)pixel`, so red is always 0, white never reaches the `0x1680` threshold, and `difOff` stays at its initial `0x8080` = 0.5/0.5 whatever the pixels are. It is not free: 65,536 draws and one read-back per pass (`(w/4)·(h/4)` quads per pass); 64 ms at 320×240 in a release build, 224 ms in debug. **Minimal `src/` change for later** (M4.3a or whoever owns `3dlib`): drop the `TestScreen();` call at the end of `C3dDevice::CreateRenderer` (`Device.cpp`); the result is the default it already has.
- **Lazy render-target lock.** `CRenderer::Flip` locks and unlocks the target every frame. The lock returns a buffer whose pages are protected; the first access faults and only then is the frame read back (`bf_gfx_read_pixels`, logical), the first write faults once more and marks it written, and only a written lock is written back on unlock. An untouched lock costs two `mprotect` calls. The fault handler (SIGBUS and SIGSEGV) is (re)installed at each lock when it is not current, and passes every other fault to the handler it replaced, so a crash reporter installed before or after keeps working (checked). Under lldb the faults stop the program as `EXC_BAD_ACCESS`; `settings set platform.plugin.darwin.ignored-exceptions EXC_BAD_ACCESS` (before `run`) and `process handle -s false -p true SIGBUS SIGSEGV` let them through.
- **Backup and restore.** A `Blt` of the whole target into an offscreen surface of its size becomes `bf_gfx_backup_frame`, and the reverse `bf_gfx_restore_frame`: the fade in `Mode.cpp` never reads back. If the CPU needs that surface's pixels (`TestScreen` locks its copy), they are read then: straight from the target if nothing has drawn since, otherwise by saving the frame natively, restoring, reading, and putting the frame back.
- **Colour keys.** Texture colour keys are not needed on the GPU (`CTexture::Update` writes key colours as alpha 0); `COLORKEYENABLE` is ignored. Offscreen surfaces honour their source key in `BltFast(SRCCOLORKEY)` / `Blt(KEYSRC)` (`CSurface::DrawSurface`).
- **Surface DCs** (`CRenderer::TextOutScreen`, `GetTextSize`): `GetDC` hands out, as the `HDC`, a `bf_text_canvas` (port/native/text) over a staging bitmap pre-filled with opaque pixels; the client's `CDCSurface` and `DrawDC` (src/3dlib) draw on it with `bf_text_canvas_draw`, which writes `0x00RRGGBB` and marks the text's cell, so on `ReleaseDC` the alpha-0 pixels inside the canvas's drawn rectangle are exactly what was drawn and only they are written into the surface. Nothing is read back, and the rest of the target keeps its native resolution.
- **A part of the back buffer shown in the window** (M12.4a). `Blt` to the primary with a source rectangle smaller than the target stretches that rectangle over the window, as DirectDraw stretches to the destination (the client area): `CBink::BinkShowNextFrame` copies the movie to the top left of the back buffer and blits its 512x347 rectangle. The adapter draws the rectangle as a texture over the whole target (linear filter) and presents. The pixels come from the lock buffer when nothing has changed the target since the client wrote them back, else from a read-back of the rectangle. Its state and texture are its own: the device sends the client's state and textures again before its next draw (`Global::own_draws`). The destination rectangle is not read; the window always shows the whole target. Counter `d3d.part_presents`.
- **States** pass through: the gfx enumerations carry the Direct3D 7 numbers. Render and stage states are stored as set (for the `Get` calls) and translated into one `bf_gfx_state`, handed to gfx before the next draw.

## Build and test

```sh
cmake --preset debug && cmake --build --preset debug --target bf_compat_d3d bifrost-compat-d3d-test
build/cmake/debug/compat/d3d/bifrost-compat-d3d-test     # optional argument: output directory
```

The test runs the call sequences of `3dlib` through the COM names, offscreen: `C3dDevice::Init` (windowed, back buffer, z-buffer, the initial states by number), `CreateRenderer`'s queries, `TestScreen` as written (and its time), `CTexture::Create`/`Update`/`UpdateMipmap`/`ClearSurface`/`CopyTexture` in all four formats, a frame of `FlushRenderList`'s opaque, fog, lightmap (`lmtlvertex3d`, `CULL_CW`), alpha, emissive, indexed and UI passes, `DrawBoxScreen`'s untextured box, `CSurface::DrawSurface`, a render-target DC, `Flip`/`ShowFrame`/`CloneFrame`, screenshot and screen-effect locks, `BackupFrame`/`RestoreFrame`, clears, and `DestroyObjects`' reference counts (both 0). Pixels are checked numerically (texels exactly at 1:1; blends within 1–2). It draws a fake glyph on the render target's canvas. It writes `compat-d3d.png`; `test/reference/` holds the reviewed capture (synthetic textures only) and its SHA-256, identical in the debug, release and ASan builds on an M2 Ultra, macOS 27.2.

## Open

- The client's call sites have not run against it yet (the client does not link); the test copies their patterns.
- Full screen: `SetDisplayMode` and the flip chain are accepted, the window is the application module's business. A primary created as the render target itself (`Init` without `D3DFW_BACKBUFFER`, never used) is drawn into but never presented.
- A viewport smaller than the target clips clears only (the client's viewport is always the whole target).
- The z-buffer the client creates is 16-bit; gfx keeps its 32-bit float depth.
